# CS 210 Portfolio Reflection
## Summarize the project and what problem it was solving.
For my CS 210 portfolio artifact, I selected the Corner Grocer project. The purpose of this program was to help a grocery store analyze daily purchase data and determine how often each item was bought. The store needed this information so it could make better decisions about how to organize its produce section. The program reads item names from an input file, counts how often each item appears, allows the user to search for the frequency of a specific item, displays all item frequencies, creates a text-based histogram, and writes the frequency data to a backup file.

## What did you do particularly well?
One thing I did particularly well in this project was organizing the program using a class-based design. I created a GroceryTracker class to keep the file processing, item counting, and display functions grouped together in a logical way. I also think I did well in building a menu-driven interface that gave the user multiple ways to interact with the data. Another strength was using a map to efficiently store item names and their frequencies, which made the program both simpler and more effective.

## Where could you enhance your code? How would these improvements make your code more efficient, secure, and so on?
One area where I could enhance the code would be by separating the project into multiple files, such as a header file and implementation file, instead of keeping everything in one source file. This would improve maintainability and organization. I could also add more advanced input validation for item-name searches and possibly make the search less sensitive to capitalization. Another improvement would be to expand error handling for file access and unexpected input. These changes would make the program more secure, more user-friendly, and easier to scale or modify later.

## Which pieces of the code did you find most challenging to write, and how did you overcome this? What tools or resources are you adding to your support network?
The most challenging part of this project was making sure the file input/output and menu system worked correctly together. I needed to make sure the program could read the input file, generate the correct frequencies, create the backup file, and then still allow the user to interact with the menu without errors. I overcame this by testing the program step by step, verifying each menu option, and checking the generated output file. I also relied on course materials, examples of file handling in C++, and repeated test runs. Moving forward, I am adding reference guides for C++ file handling, maps, and input validation to my support network because those resources will continue to be useful in future projects.

## What skills from this project will be particularly transferable to other projects or course work?
Several skills from this project will transfer to future course work and projects. These include reading from and writing to files, organizing code with classes, using maps to manage data, validating user input, and designing menu-driven programs. The project also strengthened my ability to break a larger problem into smaller parts and solve each part systematically. These are important programming skills that will apply not only in C++ but also in other languages and software development settings.

## How did you make this program maintainable, readable, and adaptable?
I made this program maintainable and readable by using meaningful variable and function names, adding comments to explain the main parts of the code, and grouping related functionality into a class. This made the program easier to follow and update. I also designed the menu options so each major task had a dedicated function, which improves adaptability because changes can be made to one part of the program without affecting everything else. Using a map also made the design more flexible because the program can handle any number of grocery items without needing to hard-code them.
